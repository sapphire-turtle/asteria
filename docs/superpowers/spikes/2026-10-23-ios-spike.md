# iOS 試作のチェックリストと結果

spec §8 の4項目を、実機（と CI のシミュレーター）で確かめるための手順と、結果を貼る場所。試作の置き場所と Mac での手順は [`spikes/ios/README.md`](../../../spikes/ios/README.md) にある。

## 目的と判断の基準

| 項目 | 合格の基準 |
|---|---|
| egui | セーフエリアの内側に収まり、タップ、スクロール、キーボード、回転、バックグラウンドからの復帰が実用的に動く |
| 音声 | ロックしたまま 2 分以上鳴り続け、ロック画面とコントロールセンターから一時停止と再開ができる。中断とイヤホンを抜いたときに止まる |
| Opus | libopus との SNR が 60 dB 以上、iPhone の release ビルドで 20 倍速以上、license が GPL-3.0 と両立する候補が1つ以上あれば、オフライン用の音声は Ogg Opus にする。なければ Ogg Vorbis（symphonia で復号できる）にする |
| 写真 | HEIC の原本、Live Photos の組、4K 動画、iCloud にしかない写真を、メモリを増やさずに読める |

## 手順

1. README の「Mac での手順」でアプリを実機に入れる。
2. Opus の計測だけは **Release ビルド**で行う。Xcode で Product > Scheme > Edit Scheme > Run > Build Configuration を **Release** にして Run し直す。Debug のままだと画面に「Debug ビルドの値です」と出て、レポートに `opus.build: debug` が入る。その値は 20 倍速の判断に使わない。
3. 各画面の項目を試し、OK / NG を押す。押した結果はレポートの `check.<画面>.<項目>` に入る（押さなかった項目は `unchecked`）。
4. 最後に Report 画面の「コピー」でレポート全文をコピーし、下の「端末のレポート」に貼る。貼る前に `photos.sample.*` の行（写真の撮影日時と元のファイル名が入る）を消すか、日時とファイル名を削る。残したいときはこの文書ではなくチャットにだけ貼る。ハッシュ・件数・サイズはそのままでよい。

### Display 画面（`check.display.*`）

| レポートのキー | 確認方法 |
|---|---|
| `check.display.safe_area` | ノッチ / Dynamic Island、ステータスバー、ホームインジケーターの下に内容や下部バーが潜らない。縦横どちらでも確認する |
| `check.display.tap` | ボタンやタップのカウンターが押した回数どおりに動く。複数の指も数えられる |
| `check.display.scroll` | 縦スクロールが指に付いてくる。慣性があり、タップと取り違えない |
| `check.display.keyboard` | 入力欄をタップするとキーボードが出て、入力欄が隠れない。閉じると元に戻る |
| `check.display.cjk` | 日本語が豆腐にならずに表示される（`fonts.cjk` も確認） |
| `check.display.rotate` | 回転しても描画が崩れず、セーフエリアが追従する |

追加で（Review Focus 2）：ホーム画面に戻ってからアプリに戻る。ロックして解除する。どちらも落ちず、描画が戻ること（wgpu のサーフェスの作り直し）。結果は「気づいたこと」に書く。

### Opus 画面（`opus.*`）

1. Release ビルドであることを確かめる（画面に Debug の警告が出ていない）。
2. 「計測する」を押す。別スレッドで全候補を 3 回ずつ復号し、x_realtime の中央値を出す。
3. レポートの `opus.<name>.x_realtime`、`opus.<name>.pcm_hash`、`opus.<name>.error` を読む（`<name>` は `opus-decoder`、`opuscule`、`opus-pure`）。
4. 判断：決め方は変わらない。libopus との SNR が 60 dB 以上、iPhone の Release で実時間の 20 倍以上（x_realtime が 20 以上）、ライセンスが GPL 互換、で合格。SNR は Linux の表（libopus との比較）を使う。`error` が出ていれば原因を調べる。
   - `pcm_hash` が Linux の表と一致すれば、Linux の SNR はそのまま端末にも当てはまる。
   - 一致しなくても NG ではない。aarch64 や Apple の libm は x86_64 Linux と最後の数ビットが違うことがある。調べるときは macOS arm64 の表と比べる。この表は CI の `ios` ジョブのログ（「Compare Opus decoders (aarch64 / Apple libm)」の手順）に出る。ffmpeg が無いので SNR は出ないが、`pcm_hash` と x_realtime は見られる。

SNR は libopus との比較。opus-decoder は SNR が高いが、この機械の release でも 3.4 倍速で遅い。

### シミュレーター CI（Task 3）

- アーティファクト `ios-simulator`（スクリーンショットとコンソール出力）。
- アプリは iOS 26.5 のシミュレーター（Xcode 26.6）で起動して描画する。
- CJK のフォントは Hiragino Sans が見つかる。
- 見つかったこと：wgpu の既定の limits がシミュレーターの Metal アダプターを超える（`max_inter_stage_shader_variables` が 16 で、アダプターは 15）。デバイスの作成に失敗するため、要求する limits をアダプターの値に切り詰めて回避した（`lib.rs` の `wgpu_options`）。実機でも同じ処理が無害であることを確かめる。

### 気づいたこと（ユーザー記入）

- 実機・iOS のバージョン：iPhone 15 Pro、iOS 27.0.1
- ホーム画面 / ロックからの復帰：落ちず、音声も鳴り続けた（`check.audio.background_foreground: ok`）
- 体感（タッチ、スクロール、キーボード）：タップとスクロールは OK。キーボードは英語は入力できるが、日本語は入力できない
- そのほか：unchecked の項目は、OK / NG ではなく確かめられなかったもの

## iOS 27 実機での判定（2026-10-25）

| 項目 | 判定 | 根拠と残り |
|---|---|---|
| egui | 日本語入力を除いて合格 | セーフエリア、タップ、スクロール、回転、日本語の表示は OK。日本語入力ができない（下記） |
| 音声 | 合格（中断からの再開は未確認） | ロック中の 2 分、ロック画面とコントロールセンターの操作、イヤホンを抜いたときの停止、ホームからの復帰は OK。`check.audio.interruption_resume` は未確認 |
| Opus | 合格。オフライン用の音声は Ogg Opus にする | iPhone の Release で opus-pure が 911 倍速、opuscule が 576 倍速（基準は 20 倍）。SNR はどちらも 71.2 dB（Linux の表）、license は BSD-3-Clause と MPL-2.0。opus-decoder は 7.8 倍速で不合格 |
| 写真 | 一部合格 | HEIC の原本と Live Photos の組は OK。660 枚、動画 12、Live Photos 294 の列挙が 94 ms。許可しない / 選択した写真のみ、4K 動画、iCloud にしかない写真は未確認 |

### iOS 27 の実機で起動しない（UIScene）

- iOS 27 の SDK でビルドしたアプリは、UIScene のライフサイクルに対応していないと、iOS 27 の実機で起動直後に止められる（`_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption` で SIGTRAP）。iOS 27.1 のシミュレーターでは止められない（Debug でも Release でも起動する）。
- winit 0.30.13 の iOS 実装は UIScene に対応しておらず、UIWindow をシーンなしで作る。corundum-framework（eframe / winit）で作る iOS アプリはすべて当てはまる。
- 試作での回避：Info.plist に `UIApplicationSceneManifest` を足し、`main.m` のシーンのデリゲートで、winit が作ったウィンドウを接続したシーンにつなぐ（`makeKeyAndVisible` を差し替えて、シーンがあれば `windowScene` を設定する）。この回避で実機は起動し、ホームからの復帰も問題なかった。本来は corundum-framework か winit で直す。

### 日本語入力ができない

- winit 0.30 の iOS の view は `UIKeyInput`（`insertText:` と `deleteBackward`）だけを実装し、`UITextInput` を実装していない。変換中の文字（marked text）を扱えないので、日本語の IME が使えない。英語のように確定した文字だけを送るキーボードは使える。
- corundum-framework か winit で `UITextInput` を実装するまで、iOS のクライアントでは日本語を入力できない。

### 音声で見つかったこと

- イヤホンを挿したとき（route change の `NewDeviceAvailable`）に出力のストリームがエラーになった（`audio.stream_error: Audio route changed`）。本実装では route change でストリームを作り直す。
- 端末の出力が 44.1 kHz だったので、48 kHz の Opus を線形補間で変換していた。本実装では AVAudioSession に 48 kHz を求めるか、質の良いリサンプラーを使う。

### Opus の pcm_hash

opus-decoder と opuscule の `pcm_hash` は、Mac のシミュレーター（Debug）と iPhone（Release）で一致し、Linux とは違う。opus-pure は Linux、シミュレーター（Debug）、iPhone（Release）ですべて違う。上の手順のとおり、違っても NG ではない。

## corundum-gui の気づき

後で sapphire-framework にイシューを立てる元にする。

2026-10-25 追記：corundum-gui は sapphire-turtle/corundum-framework に移ったので、試作もそちらに切り替えた（0.1.0）。以下のセーフエリア、アイコン、wgpu の limits は corundum-framework 側で直っているので、試作の回避策は外した。セーフエリアは `Shell` が守り、iOS では `window::run` が画面全体に描く。limits は `gpu::wgpu_options` が adapter に合わせる。実機のチェックリストは移行後の試作で行う。以下は移行前の記録。

### セーフエリア

- 隙間：egui はセーフエリアの inset を報告する（`ctx.input(|i| i.safe_area_insets())`。シミュレーターの iPhone で上 62 pt、下 34 pt）が、corundum-gui の `Shell` は内容をステータスバー / Dynamic Island の下まで描き、下部バーをホームインジケーターの上に重ねる。
- 証拠：Task 3 の CI のスクリーンショット（アーティファクト `ios-simulator`）。
- 試作での回避：`SpikeApp::ui` で、`Shell` に渡す前に root の領域を 四辺の inset で `Frame::NONE.inner_margin(..)` の CentralPanel に包む。本来は corundum-gui 側で直すべきで、イシューにする。

### アイコンの不足

corundum-gui に display、speaker、image、clipboard のアイコンがない。Task 2 では代わりに info、chevron_right、folder、refresh_cw、file_text を使った（`screens/mod.rs` の `Screen::destinations`）。

### タッチでの使い勝手

iOS 27 の実機（iPhone 15 Pro）で、タップとスクロールは問題なかった。日本語入力ができないことは上の「日本語入力ができない」に書いた。
