# project-asteria

## photos サーバーの起動

```sh
# ライブラリ（既存でも可）と設定ファイルを作り、所有者のトークンを一度だけ表示する。
asteria-photos-server init --library ~/Pictures --owner me --config ~/.config/asteria/photos.toml
# <library>/.asteria/users.toml にいる別のユーザーのトークンを追加する。
asteria-photos-server token add --config ~/.config/asteria/photos.toml --user <USER_ID>
# 起動する（Ctrl-C で安全に停止）。
asteria-photos-server serve --config ~/.config/asteria/photos.toml
```

- `init` は既存の設定ファイルを `--force` なしでは上書きしない。標準出力に出るのはトークンだけ。
- 既定の待ち受けは `127.0.0.1:7810`（`init --listen` で設定、`serve --listen` で上書き）。
- キャッシュ（索引とサムネイル）は `$XDG_CACHE_HOME/asteria-photos/<library-id>/`（通常は `~/.cache/...`）にあり、消しても問題ない。評価やタグはライブラリ内のサイドカーが原本。
- `token add` は設定ファイルを書き換えるだけ。動いているサーバーには再起動で反映される。`init --force` は設定ファイルを作り直すので、既存のトークンはすべて置き換わる。
- トークンは平文（素の HTTP）で流れる。サーバーは LAN か Tailscale などの VPN の中だけで公開し、インターネットに直接出さない。
- 1つのライブラリを扱うサーバーは1つだけ。`serve` は `<library>/.asteria/server.lock` をロックし、2つ目はエラーで終了する。
- サムネイルには `vipsthumbnail`（libvips-tools）、動画には `ffmpeg` が必要。ログは `RUST_LOG` で調整（既定 `info`）。

## photos クライアントの起動

```sh
# Linux では eframe のためにいくつかのシステムパッケージが要る（Debian/Ubuntu の名前）。
sudo apt install libxkbcommon-dev libwayland-dev libx11-dev libxcb1-dev libgl1-mesa-dev
cargo run -p asteria-photos --release
```

- クライアントは `asteria-photos-server` が配信するライブラリを見るもの。サムネイルはサーバーが作るので、libvips や ffmpeg は要らない。
- 初回はサーバーが未登録なので、設定が「サーバー」ページで追加フォームを開いた状態で始まる。名前、アドレス（`http://192.168.1.10:7810` など）、`init`（または `token add`）が表示したアクセストークンを入れ、「接続を確かめる」で確かめてから保存する。左のレールで「ライブラリ」を開くと写真が見える。
- サーバーは複数登録できる。ステータスバー（右下。幅が狭いときはアイコンだけ）に使用中のサーバーと接続の状態が出る。メニューから別のサーバーを選ぶと切り替わり、「サーバーを管理…」（設定 › サーバー）では追加、編集、削除ができる。使用中のサーバーは次回の起動でも覚えていて、切り替えるとライブラリのルートから表示し直す。
- サーバーにつながらない、トークンが通らない、バージョンが合わない、といったときは、ライブラリに理由と「もう一度」ボタンが出る。オフライン用のキャッシュはまだない。
- サーバーとトークンは、アプリの設定ディレクトリの `servers.toml` に保存される（Linux は `~/.config/asteria-photos/`、macOS は `~/Library/Application Support/asteria-photos/`、Windows は `%APPDATA%\asteria-photos\`）。Unix ではこのファイルを自分だけが読める権限（0600）にする。トークンは OS のキーチェーンには入れない。取得したサムネイルはアプリのキャッシュディレクトリ（Linux は `~/.cache/asteria-photos/`）に置かれ、消しても問題ない。
- 写真をクリックで選ぶと、右にプレビューと詳細が出る。グリッドでは矢印キーで選択が動き、Enter（またはダブルクリック）で選んだ写真が全画面表示になる。全画面では左右キーで同じフォルダ内を前後に移動し、Esc で閉じる。
- 詳細ペインでは、評価（星をクリック。同じ星をもう一度押すと解除）、カラーラベル、キーワードと階層タグ、説明（入力欄からフォーカスが外れると保存）を編集できる。編集はサーバーがライブラリのサイドカーに書き込む。サーバーがサイドカーを読めない写真は、理由つきで読み取り専用になる。

## photos クライアントからのアップロード

- デスクトップの photos ウィンドウに、ファイルやフォルダをドラッグ＆ドロップする（重ねている間は「Inbox に送る」と出る）。サーバーにつながっていないと送れない。進み具合は「アップロード」画面とステータスバーの件数で見られる。
- ファイルはライブラリの `Inbox/` の下に置かれる。フォルダは中の構造を保って `Inbox/<フォルダ名>/…` に、ファイルは `Inbox/` の直下に置く。拡張子を除いた名前が同じファイル（HEIC と MOV、写真と XMP）は組にして一緒に送る。
- 送るのは写真、動画、その XMP サイドカーだけ。それ以外と隠しファイルは送らず、件数を出す（「直近のドロップのうち N 件は対象外でした」）。Lightroom 式の `IMG_0001.xmp` は、同じ名前のメディアが1つだけならそのサイドカーとして送り、複数に当てはまるときは送らずに警告を出す。
- ライブラリに既にあるファイルは送らず、「ライブラリにあります」のまま、「保存」か「破棄」を選ぶまで待つ（「すべて保存」「すべて破棄」もある）。ほかのファイルはその間も送られる。再録盤のように、別の写真や曲が同じ payload を持つことがあるので、自動では捨てない。失敗したものは「再試行」、1件の送信は「取り消し」で止められる。
- 中断した送信は、続きから再開する。アプリを閉じて開き直したあとも同じで、送信キューはライブラリごとにアプリのデータディレクトリへ保存される。ローカルのファイルが変わっていたら最初から送り直す。サーバーにつながらないときは待って、あとで再試行する。
- サーバー側で、7日間データが届かなかった未完了のセッションは消える。その場合、クライアントはそのファイルを最初から送り直す。
- 上限は、1ファイル 20 GiB。ユーザーごとの未完了のセッションは合計 64 GiB、1000 個まで（超えると QUOTA エラー）。
